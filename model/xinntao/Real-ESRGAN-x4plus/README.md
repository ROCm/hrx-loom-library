# Developing Real-ESRGAN x4plus

The [model overview](OVERVIEW.md) gives the installed fetch-to-serve workflow,
presets, geometry constraints, request format, and exact upstream files. The
portable inputs are [model.json](model.json), its
[acquisition lock](model.json.lock), and the authored
[tokenizer.json](tokenizer.json). An SDK user can fetch and serve the source
package without building this repository.

## Build the provider packages

From the repository root:

```sh
bazel build --config=amdgpu \
  //model/xinntao/Real-ESRGAN-x4plus:source \
  //model/xinntao/Real-ESRGAN-x4plus:archive
```

The unsuffixed targets select the `upscale` preset; the `_lifecycle` suffix
selects the other preset. `source` retains text and `archive` uses relocatable
bytecode. Each produces a selected `model.json`, a deployment `serve.json`,
and the complete program closure. The checkpoint remains an acquisition
descriptor and never enters Bazel's repositories, action inputs, or content
cache. The tokenizer is authored here, because the checkpoint publisher ships
none, and is packaged as an asset.

The model-owned [program package](program/README.md) is self-contained: it
links no shared motifs. `weights.loom` is an explicit auxiliary compiler input
in every representation and describes runtime parameter preparation.

Generate the standalone reference without acquiring checkpoints:

```sh
bazel build //model/xinntao/Real-ESRGAN-x4plus:reference
```

The result combines the overview with tables generated from the card, so it
can be published independently of this README.

## Acquire and test

Provision the installation once:

```sh
loom-fetch model/xinntao/Real-ESRGAN-x4plus/model.json \
  --preset=upscale --output=../real-esrgan-x4plus
```

The authored lock covers the checkpoint at its pinned revision and the local
tokenizer. Both presets read the same files.

The geometry test requires no learned weights:

```sh
bazel test --config=asan --config=amdgpu \
  //model/xinntao/Real-ESRGAN-x4plus/test/...
```

Run the full image regression against the provisioned installation:

```sh
bazel test --config=asan --config=amdgpu \
  --strategy=TestRunner=standalone \
  --test_env=LOOM_MODEL_ASSETS="$(realpath ../real-esrgan-x4plus)" \
  //model/xinntao/Real-ESRGAN-x4plus/test:image_source_test \
  //model/xinntao/Real-ESRGAN-x4plus/test:image_archive_test
```

These explicit `manual` tests run the real server, compare complete decoded
images, exercise a geometry change and both base64 alphabets, reject invalid
requests, and join shutdown. The `_lifecycle` tests additionally exercise
concurrent replay and client disconnection.
[Test documentation](test/README.md) describes the reference boundaries.

The card, lock, current programs, server, and checker determine test cache
identity. A cached test reads no external weights. Changing provisioned bytes
without updating the lock intentionally permits reuse of that cached result.

A built package can also be fetched directly. Publication locks describe the
actual output bytes and are generated outside Bazel:

```sh
mkdir -p .reports/real-esrgan-x4plus
PROGRAMS="$(realpath bazel-bin/model/xinntao/Real-ESRGAN-x4plus/archive)"
loom-fetch "$PROGRAMS/model.json" --offline --update-lock --lock-scope=all \
  --lockfile="$PWD/.reports/real-esrgan-x4plus/archive.lock.json" \
  --output="$PWD/.reports/real-esrgan-x4plus/archive"
loom-serve --device=amdgpu --model=./.reports/real-esrgan-x4plus/archive/model.json
```

This offline example requires the checkpoint in the Hugging Face cache, or an
equivalent named origin override. The source lock participates in Bazel's
test identity; it does not attest to newly generated bytecode. Subsequent
acquisitions of the built publication use its new lock without `--update-lock`.
