# Real-ESRGAN x4plus model checks

`geometry_test.loom` checks image admission and cohort keys at their request
boundaries on the VM, without learned parameters. Admission cases cover the
smallest and largest output on each axis, the two preset geometries, a
non-square geometry, zero and negative extents, unaligned extents, a width
below the 256-pixel minimum, and one alignment step past each 4096-pixel
limit. Tag cases check that transposed geometries select distinct stages.

The convolution kernel's numerics are checked end to end by the regression
below rather than by a separate corpus. The [development
guide](../../../../docs/development.md#build-and-check) covers ordinary
execution, optional instrumentation, and benchmarks.

## Full model regression

`image_check.py` consumes a built card plus a `loom-fetch` installation
provided through `LOOM_MODEL_ASSETS`. Programs always come from the build;
the checkpoint stays in the external installation and is shared in place. The
test trusts that file to match the authored lock, which is a declared Bazel
input. No checkpoint is downloaded, prepared offline, or archived by the test
action.

The input image is generated by the checker rather than stored: red and green
ramp across the two axes, and blue alternates between a hashed texture and a
flat field in 8×8 blocks, so the upscaler sees gradients, flat regions, sharp
edges, and high-frequency detail. The checker launches and joins a native
server, sends that pattern as the base64 prompt, decodes the RGBA8 PNG
response, verifies opaque alpha, and compares whole RGB digests from
`reference.json` at the preset geometry and at 768×400. The same input in the
URL-safe alphabet, and with a seed, must produce identical pixels.

Invalid requests must be rejected before generation and leave the server
serving: unaligned output extents, an output past the width limit, a size that
disagrees with the prompt length, a prompt one pixel short, characters outside
both base64 alphabets, more than one image, and deployment options. A valid
request follows the rejections.

The digests establish port equivalence and determinism for the pinned
checkpoint; they are not a perceptual-quality evaluation or a performance
measurement. They were pinned after comparing the served output with the
PyTorch reference implementation on the same input. Real-ESRGAN has no
sampling, so the only differences are BF16 operand rounding and accumulation
order.

The decoder is test-only and uses the Python standard library. Independent
filtered rows test its five PNG predictors, checksum handling, geometry, and
rejection of unsupported formats; separate cases check the generated input
and both prompt alphabets. The installed model itself runs native Loom
programs and needs no Python model implementation or preparation script.

Lifecycle packages also check concurrent deterministic requests, graceful and
reset-peer disconnection, terminal outcome accounting, and a subsequent clean
replay. A disconnect can race successful completion; either terminal outcome
must retire the request exactly once.

The full tests are explicit `manual` targets. Their card, lock, providers,
server, checker, and configuration participate in cache identity. Editing
external weights without updating the lock intentionally does not invalidate
a cached result. The parent README gives provisioned execution commands.
