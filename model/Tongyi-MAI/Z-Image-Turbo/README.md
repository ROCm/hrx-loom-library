# Developing Z-Image-Turbo

The [model overview](OVERVIEW.md) gives the installed fetch-to-serve workflow,
presets, geometry constraints, and exact upstream files. The portable inputs
are [model.json](model.json) and its [acquisition lock](model.json.lock). An
SDK user can fetch and serve the source package without building this
repository.

## Build the provider packages

From the repository root:

```sh
bazel build --config=amdgpu \
  //model/Tongyi-MAI/Z-Image-Turbo:source \
  //model/Tongyi-MAI/Z-Image-Turbo:archive
```

The unsuffixed targets select the `image` preset. Suffixes
`_bounded_workspace` and `_lifecycle` select the other presets; for example,
`:archive_bounded_workspace` contains the model with its 1.5 GiB workspace
policy. `source` retains text and `archive` uses relocatable bytecode. Each
produces a selected `model.json`, a deployment `serve.json`, and the complete
program closure. The checkpoints and tokenizer remain acquisition descriptors;
none enters Bazel's repositories, action inputs, or content cache.

The model-owned [program package](program/README.md) composes the text encoder,
transformer, and VAE. Generic algorithms remain under `motif/tensor`; model
providers own shapes, targets, and configuration. `weights.loom` is an explicit
auxiliary compiler input in every representation and describes runtime
parameter preparation.

Generate the standalone reference without acquiring checkpoints:

```sh
bazel build //model/Tongyi-MAI/Z-Image-Turbo:reference
```

The result combines the overview with tables generated from the card, so it
can be published independently of this README.

## Acquire and test

Provision the installation once:

```sh
loom-fetch model/Tongyi-MAI/Z-Image-Turbo/model.json \
  --preset=image --output=../z-image-turbo
```

The authored lock covers the transformer, the three text-encoder shards, the
VAE, and the tokenizer at two pinned revisions: the original checkpoint and
the BF16 transformer file. All presets read the same files. Shared motifs
follow the model card's checkout or published snapshot through relative source
paths, with no library pins, program checksums, or origin overrides to
maintain.

Geometry, numerical, and tile tests require no learned weights:

```sh
bazel test --config=asan --config=amdgpu \
  //model/Tongyi-MAI/Z-Image-Turbo/test/...
```

Run the full image regression against the provisioned installation:

```sh
bazel test --config=asan --config=amdgpu \
  --strategy=TestRunner=standalone \
  --test_env=LOOM_MODEL_ASSETS="$(realpath ../z-image-turbo)" \
  //model/Tongyi-MAI/Z-Image-Turbo/test:image_source_test \
  //model/Tongyi-MAI/Z-Image-Turbo/test:image_archive_test
```

These explicit `manual` tests run the real server, compare complete decoded
images, exercise geometry changes and prompt truncation, reject invalid
requests, and join shutdown. The `_lifecycle` tests additionally exercise
concurrent seeded replay, changed seeds, and client disconnection. The
`_bounded_workspace` tests use the same assets and compare tiled output with
its own pinned digests, because per-tile normalization changes the pixels.
[Test documentation](test/README.md) describes the reference boundaries.

The card, lock, current programs, server, and checker determine test cache
identity. A cached test reads no external weights. Changing provisioned bytes
without updating the lock intentionally permits reuse of that cached result.

A built package can also be fetched directly. Publication locks describe the
actual output bytes and are generated outside Bazel:

```sh
mkdir -p .reports/z-image-turbo
PROGRAMS="$(realpath bazel-bin/model/Tongyi-MAI/Z-Image-Turbo/archive)"
loom-fetch "$PROGRAMS/model.json" --offline --update-lock --lock-scope=all \
  --lockfile="$PWD/.reports/z-image-turbo/archive.lock.json" \
  --output="$PWD/.reports/z-image-turbo/archive"
loom-serve --device=amdgpu --model=./.reports/z-image-turbo/archive/model.json
```

This offline example requires the checkpoint files in the Hugging Face cache,
or equivalent named origin overrides. The source lock participates in Bazel's
test identity; it does not attest to newly generated bytecode. Subsequent
acquisitions of the built publication use its new lock without `--update-lock`.
