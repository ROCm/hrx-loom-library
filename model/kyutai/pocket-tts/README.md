# Developing Pocket TTS

The [model overview](OVERVIEW.md) gives the installed fetch-to-serve workflow,
voice choices, exact upstream assets, and request behavior. Stock voices run
with the installed SDK and require no Bazel build or Python preparation step.
This page covers model development and registering custom voices.

## Build the provider packages

From the repository root:

```sh
bazel build --config=amdgpu \
  //model/kyutai/pocket-tts:source \
  //model/kyutai/pocket-tts:archive
```

`source` retains Loom text and `archive` uses bytecode. Both expose speech ABI 2
and remain inputs to runtime linking and JIT specialization. The numerical
phases share the scoped `model` checkpoint;
the tokenizer identity is `text`. CPU Loom prepares audio and initializes
rotary tables once, while the native service owns reusable voice slots.

Each target produces a selected `model.json`, a deployment `serve.json`, its
program closure, and declarations for original reference recordings.
The 219 MB learned checkpoint, tokenizer, and recordings retain their upstream
acquisition descriptors. No build contacts those origins or passes a checkpoint
through Bazel's repositories, actions, outputs, or runfiles.

The `_noncommercial` target suffix selects the four-voice variant and preset,
for example `:archive_noncommercial`. The model's provider code is shared across
both variants; only the selected card and original recordings differ.

Generate the standalone model reference with:

```sh
bazel build //model/kyutai/pocket-tts:reference
```

The resulting `bazel-bin/model/kyutai/pocket-tts/reference.md` combines the
standalone overview with facts generated from the card.

## Acquire and test

Provision the default installation once:

```sh
loom-fetch model/kyutai/pocket-tts/model.json \
  --preset=streaming --output=../pocket-tts
```

The authored lock covers both voice variants' runtime assets. Shared Unicode,
UTF-8, and sampling motifs follow the model card's checkout or published snapshot
through relative source paths. Program edits need no library pin, origin override,
or checksum update; asset verification remains intact. The pinned compiler or
local HRX override used by Bazel builds the current declared motif sources.

Hermetic numerical, text, and state cases need no learned checkpoint:

```sh
bazel test --config=asan --config=amdgpu \
  //model/kyutai/pocket-tts/program/... \
  //model/kyutai/pocket-tts/test/...
```

Full speech checks use the current built providers and provisioned assets:

```sh
bazel test --config=asan --config=amdgpu \
  --strategy=TestRunner=standalone \
  --test_env=LOOM_MODEL_ASSETS="$(realpath ../pocket-tts)" \
  //model/kyutai/pocket-tts/test:speech_source_test \
  //model/kyutai/pocket-tts/test:speech_archive_test
```

These explicit `manual` targets run a real native server, compare seeded PCM
across changing cohorts and reused rows, replay multi-chunk text, verify
cancellation through owner state and counters, reject malformed requests, and
join shutdown. The tests retain only small synthesized audio, diagnostics,
and structured results. [Test documentation](test/README.md) describes the
independent numerical and normalization references.

For the four-voice package, fetch `--preset=streaming-noncommercial` into a
separate installation, point `LOOM_MODEL_ASSETS` there, and select
`:speech_source_noncommercial_test` and `:speech_archive_noncommercial_test`.
Tests trust that provisioned assets match the authored lock. The card, lock,
built programs, server, checker, and test
configuration determine cache identity. A cache hit reads no external weights;
changing weights without updating the lock intentionally permits that hit.

A generated package is also directly fetchable. Use its absolute card path
immediately after building it and write its publication lock outside Bazel's
output tree:

```sh
mkdir -p .reports/pocket
PROGRAMS="$(realpath bazel-bin/model/kyutai/pocket-tts/archive)"
loom-fetch "$PROGRAMS/model.json" --offline --update-lock --lock-scope=all \
  --lockfile="$PWD/.reports/pocket/archive.lock.json" \
  --output="$PWD/.reports/pocket/archive"
```

This example requires the checkpoint, tokenizer, and original recordings in the
HF cache. The new lock records the built bytes; the authored source lock cannot
attest to newly generated bytecode. Subsequent fetches use that lock without
`--update-lock`.

## Register custom reference voices

A running speech deployment accepts a reference recording through the same
native media path as dictation:

```sh
curl --fail-with-body -H 'Expect:' \
  http://127.0.0.1:8080/v1/audio/voices \
  -F model=kyutai/pocket-tts -F id=narrator \
  -F 'file=@reference.wav;type=audio/wav'

curl --fail-with-body http://127.0.0.1:8080/v1/audio/speech \
  -H 'Content-Type: application/json' \
  -d '{"model":"kyutai/pocket-tts","input":"Good day.","voice":"narrator","response_format":"pcm"}' \
  --output=narrator.pcm
```

The first command completes after decoding, CPU Loom preprocessing, and learned
voice encoding. Later speech requests reuse that conditioning. WAV, MP3, FLAC,
PCM16LE, and F32LE use the same formats as transcription; raw PCM declares its
sample rate and channels explicitly. The
[voice registration protocol](https://rocm.github.io/hrx-system/loom/serving/http-profiles/#voice-registration)
covers raw uploads, removal, errors, and cancellation.

To register a recording on every load, add it to the selected service variant's
`voices` map. Origins and destination paths follow the other card assets:

```json
"voices": {
  "narrator": {
    "file": {"path": "voice/narrator.wav", "origin": "https://example.org/reference.wav"},
    "content_type": "audio/wav"
  }
}
```

The canonical preset reserves eight voices and 192 encoded blocks per voice.
References exceeding its audio or frame capacities fail explicitly. Larger
capacities must satisfy the context and rotary relationships in the card.
Uploaded voices last until removal or model unloading; the original recordings
in a card are registered again at startup. Recording licenses apply separately
from the model checkpoint.

After changing published assets, replace the asset lock with exactly the
compatible variants. Program edits require no lock update:

```sh
loom-fetch model/kyutai/pocket-tts/model.json \
  --update-lock --all-variants
```

The full checkpoint stays in the normal fetch cache. Origin overrides and
`--offline` apply to this operation, and shared assets are acquired only
once even when several variants share them.
